# 차량 에뮬레이터 설계

> 버전: 1.0.0 | 작성일: 2026-07-31 | 상태: 승인
> 관련 요구사항: FR-01, FR-08
> 문서 순서: 01 | 공통 기준: [공통 설계](00-common.design.md)

## 1. 책임

- 설정된 차량 수만큼 가상 MQTT client 실행
- 차량별 상태, `sessionId`, 증가하는 `sequence` 유지
- 고정 경로 좌표 보간
- 속도, 방향, 적재함 온도, 문 상태 생성
- MQTT v5/QoS 1 telemetry publish
- 정상·온도 상승·통신 단절·중복·지연 시나리오 실행

## 2. 차량 상태

```text
대기 -> 운행 시작 -> 배송 중 -> 상하차 -> 운행 종료
```

- 운행 중 경로의 인접 좌표 사이 이동
- 상하차 시 문 열림 상태 생성
- 냉장 장치 이상 시 온도의 점진적 상승
- 차량별 동일 발행 주기와 독립 sequence 사용

## 3. 재연결

- 연결 단절 중 생성 메시지의 메모리 buffer 보관
- 연결 복구 후 측정 시각을 유지한 순차 재전송
- 재전송 폭주를 검증할 수 있는 동시 복구 시나리오
- 프로세스 재시작 시 새로운 `sessionId` 생성과 sequence 초기화

메모리 buffer는 시뮬레이션 도구의 단순화를 위한 선택이다. 실제 단말기의 영구 저장 방식은 범위에서 제외한다.

## 4. 실행 인터페이스

초기에는 UI나 실행 중 프로세스 제어 API 없이 환경 변수, CLI, 선언형 시나리오
파일을 사용한다.

```text
simulator start --vehicles 100 --interval 1000
simulator start --scenario scenarios/reconnect-storm.json
```

시나리오 파일은 실행 후 경과 시각, 대상 차량, 단절·온도 상승·중복·지연 동작을
정의한다. CLI 세부 문법과 JSON schema는 구현 라이브러리에 맞게 조정할 수 있지만
기능 의미와 random seed 재현성은 유지한다.

## 5. 데이터 원천

- 차량 seed의 `VH-001`~`VH-100` 사용
- DB에 등록되지 않은 차량 ID의 임의 생성 금지
- 실제 도로 경로 API 미사용
- 서울 지역의 고정된 샘플 경로 사용
- 테스트 재현을 위한 random seed 설정 지원

## 6. 오류 처리

- MQTT 연결 실패의 exponential backoff
- publish 실패 건수 로그
- 설정 오류의 시작 단계 실패
- 허용 범위를 벗어난 차량 수와 발행 주기 거부

## 7. 테스트

### 단위 테스트

- 좌표 보간
- sequence 증가
- 새 세션 ID 생성
- 온도 상승·정상화
- 문 열림 상태 전이
- 고정 random seed 재현성

### 통합 테스트

- Mosquitto publish
- QoS 1 전달
- 연결 단절 후 재전송
- 중복·지연 시나리오

## 8. 완료 기준

- 차량 100대의 1초 주기 발행
- 정상·온도 이상·통신 단절 시나리오 실행
- 측정 시각을 유지한 지연 데이터 재전송
- 동일 설정과 random seed의 재현 가능한 결과
